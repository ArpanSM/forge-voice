The problem

Most voice demos show the first call and stop.

  • They talk over the caller, invent a slot, lose the caller on transfer.
  • They write before an explicit yes, or double-book on a retry.
  • They leak one tenant's data into another and cannot explain the call.

The hard parts are turn-taking, typed writes, confirmation, emergency triage, handoff, tenancy, evaluation and monitoring.

Architecture

One local stack: browser, self-hosted LiveKit, FastAPI, LiveKit Agents and LFM3. Groq is the only approved external call, and only for the hybrid LLM.

No Cloud transport, SIP, paid STT/TTS or hosted URL in this slice.

What the tool layer guarantees

  • One booking row for the offered slot.
  • Confirmation queued once.
  • Repeated “yes” returns the same booking.
  • Expired offer refreshes and re-reads.

Honest limits

This is a demo tier, not a production SLA.

Measured and stated

  • 10-turn WebRTC p95 first audio 5.3 s.
  • Barge-in yield ~0.88 s.
  • No sub-3 s, sub-2 s or sub-1 s claim.
  • One 10-turn sample per profile; production APIs must be re-measured.

Known product gaps

  • No proactive silence prompt before 3 s.
  • Degraded ZIP recognition is fragile.
  • No long-utterance turn-taking guard.
  • Local-only; no SIP, real calendar/CRM, payments or HIPAA/PCI claim.

The demo avoids the gaps: clean audio, short turns, ZIP digits one at a time and no long silence.

Every measured claim carries its caveat in the README and case study.
