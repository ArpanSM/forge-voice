Local runbook — one page

What this is: the local-only deploy and recovery steps for the Harborlight + Summit voice demo, ticket #8. The browser, token page, dashboard and admin are one FastAPI app; LiveKit is self-hosted; LFM3-Audio-2B stays on the host GPU. No Cloud transport, hosted URL, SIP, TURN or paid provider is used.

Prerequisites

  • Linux laptop with the 4 GB GPU and LFM3-Audio-2B (lfm3 audio).
  • Docker Engine + Docker Compose v2.20 or newer for the Compose path. The Compose path uses Linux host networking so the browser and the agent share LiveKit's loopback media; it is not supported on Docker Desktop/macOS/Windows in this slice.
  • curl and Python 3.12+ for the preflight and make health helpers (python3 works if it is 3.12+; set FORGE_VOICE_PYTHON otherwise). These are required even when Docker is the only runtime. The host-binary fallback additionally uses make install.
  • Set FORGE_VOICE_UID=$(id -u) and FORGE_VOICE_GID=$(id -g) if they are not 1000, so the non-root containers keep ./data, ./recordings and ./tenants user-owned.
  • Free ports: 7880/7881 LiveKit TCP, 7882 LiveKit UDP, 8000 web, 8081 agent health, 8082 LFM3.
  • A local LiveKit dev key/secret in .env.local; an optional free Groq key for hybrid.

1. First run

cp .env.example .env.local       # gitignored; never commit it
scripts/prepare_local_env.sh .   # fills a random local LIVEKIT_API_SECRET if blank
# Optional hybrid only: GROQ_API_KEY=... in .env.local or the environment
lfm3 audio                       # host GPU; wait for http://127.0.0.1:8082/health
make demo                        # Compose when Docker is available, host binaries otherwise

make demo chooses the Docker Compose stack when Docker + Compose + the daemon are reachable; otherwise it prints MODE: host-binary and uses the original host demo. It never implies Compose ran when it did not. The paths are explicit when you need them:

make demo-local       # host-binary livekit-server; no Docker
make demo-compose     # one-stack Compose path; fails if Docker/LFM3/curl/Python/a port is missing
make demo-hybrid      # same stack, LFM3 audio + Groq qwen/qwen3.8-27b as the only external LLM
make demo-hybrid-local
make demo-hybrid-compose

The Compose path waits for LiveKit, web /health, agent readiness and LFM3 /health. It fails closed with a clear message if LFM3 is down, a port is taken or a healthcheck never passes. make demo never claims the Compose stack ran when Docker is absent.

4. Daily commands

Command What it does
make logs Follow LiveKit, web and agent logs.
make health Probe LFM3, LiveKit, web and agent readiness; nonzero on failure.
make down Stop Compose. ./data, ./recordings and .env.local stay.
make reset Stop, delete synthetic calls/bookings/traces/recordings and reseed the 30-day dashboard set. ./data/backup stays.
make demo Start again.
make release TAG=v1 Stop writers, tag web/agent images and snapshot ./data into ./data/backup.
make rollback Start the previous tags; restore ./data/backup when the schema changed.
make retention Prune raw data/calls/*.jsonl and recordings/ older than 30 days.

Retention is 30 days for dashboard records, raw call traces and recordings. The web app prunes raw traces/recordings on start (the dashboard store prunes its own cache); make retention runs the same job explicitly. make reset is the explicit clean slate and reseeds the deterministic set.

5. Rollback

  1. Before an upgrade: make release TAG=v1 (or keep the previous image tags). Release stops the services first so SQLite/WAL files are copied consistently.
  2. If the schema changed, set FORGE_VOICE_SCHEMA_VERSION to the new value for that release, e.g. FORGE_VOICE_SCHEMA_VERSION=2 make release TAG=v2. The release writes .release/current, .release/previous, both schema markers and ./data/backup.
  3. make rollback reads the previous tag, stops the stack, restores ./data/backup if the recorded schema differs, then runs the previous images with up --wait --no-build.
  4. Run make health and one clean booking before declaring the rollback good.

Rollback is local and one command; there is no hosted deployment to revert. If no backup exists and the schema changed, the command fails closed rather than mixing schemas.

6. Common failures

Symptom Check Fix
LFM3-Audio-2B is not healthy lfm3 status; curl 127.0.0.1:8082/health lfm3 audio; wait for the model; check GPU memory
Port 7880/7881/7882/8000/8081 is already in use ss -ltnup make down, or stop the process using the port
Docker path fails immediately docker info; docker compose version; python3 --version; curl --version Start/install Docker, Python 3.12+ and curl; or use make demo-local
Root-owned data after Compose ls -ln data recordings tenants Set FORGE_VOICE_UID=$(id -u) and FORGE_VOICE_GID=$(id -g) in .env.local, rebuild
Browser cannot join make health; make logs Restart the stack; check LIVEKIT_URL and key/secret
Agent joins but no audio Agent log; LFM3 log; mic permission Allow the mic; confirm host.docker.internal:8082; restart agent
Token expired Browser console / web log Reload the page; tokens are 120 s by design
Groq 429 / rate limit Agent log Use make demo (fully local); do not add a paid fallback
Dashboard empty ./data; one live call Run a call; make reset reseeds
Admin edit rejected /admin error text Fix the YAML field; invalid edits never write or reload
Recording missing ./recordings; consent flag Enable recording; respect opt-out; text_only is valid
unknown_tenant /token response Use a configured tenant; unknown tenants fail closed

7. Free-tier and honest limits

  • Demo cost is $0 on free tiers + the local GPU. Production estimate is $0.03–0.06/min, not measured here. No paid fallback exists.
  • Groq free-tier limits apply only to hybrid. When exhausted, use the fully local profile.
  • Measured 10-turn p95 first audio is 5.3 s; barge-in is ~0.88 s. No sub-3 s or sub-2 s claim. Latency is report-only.
  • LFM3 is a 2B model on a 4 GB GPU; no proactive silence prompt, fragile degraded ZIP and no long-utterance guard are known limits. Use short, clean turns and digit-by-digit ZIPs.
  • No phone/SIP, real calendar/CRM/SMS, payments, HIPAA/PCI, 24/7 on-call, multilingual booking or visual workflow builder. New tenants, services and integrations are change requests (see handover.md).
