# Coding standards

## Runtime and layout

- Python **3.12**, `src/forge_voice/` package layout, typed public functions.
- Build metadata and tool config live in `pyproject.toml`; do not add ad-hoc config files.
- `make test`, `make lint` and `make corpus` must work from a clean checkout.
- Keep the first slice local: no network in unit tests and no paid provider dependency.

## Style

- Ruff is the formatter and linter. Line length is **100**; target version is `py312`.
- Use `snake_case` modules/functions, `PascalCase` classes, `UPPER_SNAKE_CASE` constants.
- Prefer small, pure functions. Side effects belong at explicit adapters and CLI edges.
- Raise specific exceptions; never return `None` to signal a validation failure.
- Sort imports automatically with `ruff check --fix`; do not hand-order them differently.

## Models and envelopes

- Use Pydantic v2 models for tenant config, scenario manifests, seed records and provider
  messages. Validate at the loader boundary, not deep inside business logic.
- Reject unknown fields (`extra="forbid"`) on configuration and manifest models.
- Tool results use the shared common envelope (implemented with the tools in #4):
  success `{ok: true, data, request_id}`, failure
  `{ok: false, error: {code, message, retryable, details?}, request_id}`.
- Error codes are stable strings from the workflow contract; never leak stack traces.
- Writes are atomic and idempotent; no model-supplied confirmation token or idempotency key.

## Tests

- pytest only. Files are `tests/test_<area>.py`; test names state behavior:
  `test_tenant_loader_rejects_zip_outside_allowlist`.
- Test at public seams: tenant loader/schema, scenario loader, corpus generator, provider.
- One behavior per test. Assert observable results, not private helpers or call order.
- Use `tmp_path` and committed fixtures. **No real network in unit tests**: use
  `FakeProvider`, or an injected in-process transport that records calls for adapter tests.
- Determinism is a contract: fixed anchors, sorted output, SHA-256 hashes, stable JSON.
- Provider tests may use `OpenAICompatibleProvider` with a recording in-process transport; they
  must never open a socket.

## Data and dependencies

- Synthetic names, numbers, addresses and calendars only. Never real customer data.
- No secrets in source, tests, fixtures, logs or error messages. `.env.example` holds
  placeholders; `.env.local` is ignored.
- The two-tenant seed fixture maps in `corpus/seed.py` are intentionally hand-authored. Adding
  a third tenant means adding a customer/bookings/calls block; this is accepted for the
   two-tenant first slice rather than building a generic fixture DSL.
- `corpus/seed.py` intentionally keeps seed models, hand-authored data, generation and
  validation in one module for #3. Splitting it would churn the fixtures without reducing
  domain coupling; revisit if a third tenant or a second fixture family arrives.
- Accepted first-slice seed smells: the `_customer_map`/`_booking_specs`/`_call_specs`/
  `_ticket_specs` lookups repeat the same pattern, `_overlaps` carries a four-value data clump,
  identifier/ZIP validation regexes are repeated, `SeedEmergencyTicket.safety_instructions_given`
  is free-form, and stale-file deletion after the hashes marker has no rollback test. These are
  deliberate two-tenant judgement calls, not hidden debt.
- Add a dependency only for a first-slice requirement; prefer the standard library.

## Corpus writes

`make corpus` never removes an existing corpus. A failed first run removes only the partial
directory it just created. It writes staged files into the existing tree with per-file
`os.replace`, publishes `hashes.json` last as the commit marker, then removes stale files. A
backup copy is used only to restore the previous corpus if a replace fails before the marker.
This is per-file atomicity, not a single directory rename.
- Audio binaries are generated by `make audio-fixtures` (LFM3 TTS) and committed with SHA-256 hashes. Tests verify the hashes offline; unit tests never call LFM3.

## Commands

```bash
make corpus   # regenerate fixtures; re-running must produce identical hashes
make test     # offline tests
make lint     # ruff check + ruff format --check
make format   # apply formatting while developing
```

## Accepted first-slice choices (#4)

- One `SQLiteAdapter` owns all synthetic ports (calendar, CRM, bookings, tickets, callbacks,
  confirmations and events) behind tenant-scoped methods. Separate databases would add ports
  without changing behavior at this size.
- The text-mode `CallRunner` uses a deterministic rule interpreter instead of an LLM; the
  policy owns the confirmation phase and exact payload, while the runner selects the caller
  turn that follows the last data-bearing turn as the read-back response. Audio mode uses the
  real LiveKit turn state instead of this turn boundary.
- Callback and transfer retries share the `idempotency` table rather than a separate transfer
  table; the transfer is simulated, so there is no provider-side transfer id to reconcile.
- Public adapter methods are serialized by one `RLock`; a nested `transaction()` is rejected
  explicitly rather than emulated with savepoints. Call inside the outer transaction through
  the documented in-transaction methods.

## Accepted first-slice choices (#5)

- The self-hosted `livekit-server` is a pinned, checksum-verified binary under `.tools/` rather
  than a Docker dependency. `make bootstrap` owns the download; `.tools/` is gitignored.
- The worker is dispatched explicitly by agent name from the token's room configuration. This
  avoids relying on automatic room dispatch, which did not start jobs reliably on the local
  server in smoke runs.
- Tenant identity is a 120 s HMAC claim inside the LiveKit participant metadata. Room names and
  query parameters are not trusted; the claim is verified before any policy state exists.
- The LiveKit browser client is vendored under `src/forge_voice/web/static/` so the local page
  has no CDN dependency.
- Emergency triage is intercepted deterministically in the agent's `llm_node`, before the model.
  The model still handles booking, but it cannot decide whether an emergency exists or speak a
  different safety script.
- The LFM3 TTS fixture generator passes a fixed seed and `temperature: 0`. The local server is
  deterministic for a fixed model build; hashes capture the committed bytes.
